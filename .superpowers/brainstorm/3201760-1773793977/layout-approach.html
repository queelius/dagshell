Layout: How should the explorable be structured?

The terminal is the core. The question is what surrounds it.

A

Terminal Only (with inline lessons)

A single full-width terminal. Lessons, philosophy callouts, and filesystem visualization all happen inside the terminal output — like a real shell tutorial. The filesystem tree is shown via tree command, not a separate panel.

Pros

  • Simpler to build
  • Feels most authentic — like actually using a terminal
  • Works great on mobile
  • Matches the "intro to Linux" framing

Cons

  • No persistent visual of the filesystem tree
  • Less "explorable", more "tutorial"
B

Terminal + Live Filesystem Tree

Split pane: terminal on the left, a collapsible tree view on the right that updates in real-time as you run commands. The tree shows files, directories, permissions, and sizes. Optional toggle to see the raw JSON/DAG.

Pros

  • Visual feedback makes structure visible
  • The "aha moment" of seeing the tree grow as you type commands
  • Can highlight which nodes changed
  • More distinctive as an explorable

Cons

  • More complex to build
  • Needs responsive design for mobile (collapse to tabs?)
  • Risk of visual clutter
C

Terminal + Contextual Sidebar

Terminal is primary. A narrow sidebar appears only when relevant — showing a filesystem tree during navigation lessons, a permission matrix during chmod lessons, a pipe diagram during composition lessons. Disappears when not needed.

Pros

  • Best of both worlds — visual when it helps, clean when it doesn't
  • Each lesson can have a bespoke visualization
  • Feels like the terminal is "teaching you"

Cons

  • Most complex to build
  • Need to design multiple visualization types
  • Transitions between sidebar states need to feel natural
